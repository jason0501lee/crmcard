# CRM 名片系統 — 產品需求文件 (PRD)

> 版本：Phase 1 MVP　|　最後更新：2026-05-29
> 角色：本文件由 PM 與需求方一問一答共同建構，作為後續開發依據。

---

## 1. 產品願景

一套「拍名片 → AI 擷取 → 存進資料庫」的 CRM 名片系統，分兩階段：

- **Phase 1（本文件範圍）**：收集**他人**名片 → 數位化進個人 CRM，可瀏覽、搜尋、管理關係。
- **Phase 2（後續）**：建立**自己的**數位名片（含 Logo、QR Code），可對外展示與分享。

兩階段共用同一套資料模型，Phase 2 為 Phase 1 的反向複用，邊際成本低。

---

## 2. Phase 1 核心流程

```
使用者登入
  → 手機相機拍名片（正面 + 背面）
  → 上傳至 Supabase Storage
  → AI（Claude Vision）擷取結構化 JSON
  → 【人工確認 / 修正頁】（必備：AI 會錯，存檔前可改）
  → 寫入 Supabase（contacts + 子表）
  → 聯絡人列表 / 搜尋 / 詳情 / 編輯
```

---

## 3. 技術決策摘要（已拍板）

| 項目 | 決策 | 理由 |
|---|---|---|
| 平台形態 | **Next.js PWA** | 免上架、跨平台、手機瀏覽器開相機、與 Supabase 整合直接 |
| 擷取路線 | **多模態 LLM 直出 JSON** | 一步到位、中英混排與版面推理強 |
| 擷取模型 | **Claude Vision（質量優先）**，包成可抽換介面 | 欄位判斷與 JSON 遵從度最穩；日後可換 Gemini 省成本 |
| 後端 | **Supabase**（Auth + Postgres + Storage） | 一站式 |
| 帳號模式 | **單人帳號 + RLS 隔離**（每人只見自己的聯絡人） | CRM 為私密資產；團隊共享留待後期 |
| 多值欄位 | **正規化子表**（phones、social_links） | 查詢/統計能力強、資料乾淨 |
| CRM 欄位 | **標籤 Tags + 備註 Notes** | 低成本高價值，升級為真正 CRM |
| 拍攝範圍 | **正面 + 背面合併擷取** | 名片背面常為英文或 QR |

## 4. 功能範圍

### 4.1 Phase 1 必做（In Scope）
- [ ] 帳號註冊 / 登入（Supabase Auth）
- [ ] 相機拍照（正面 + 背面）/ 從相簿選圖，上傳 Storage
- [ ] AI 擷取名片欄位 → 結構化 JSON
- [ ] 人工確認 / 修正頁（含原圖對照）
- [ ] 聯絡人 CRUD（建立、列表、詳情、編輯、刪除）
- [ ] 多支電話、多個社群（子表）
- [ ] 標籤 Tags、備註 Notes
- [ ] 關鍵字搜尋（姓名 / 公司 / 標籤）
- [ ] RLS：使用者只能存取自己的資料

### 4.2 明確不做（Out of Scope，留 Phase 2 之後）
- 自己的數位名片製作、QR Code 產生與分享頁
- 公司 Logo 自動辨識/抓取（Phase 1 可手動上傳，非必填）
- 團隊 / 組織共享、角色權限
- 跟進狀態、結識日期/場合（業務漏斗）
- 批次多張掃描
- 重複聯絡人偵測 / 合併
- 匯出 vCard / CSV、與外部 CRM 同步

> 待確認的小項：掃描到的名片上若印有 QR Code 是否要自動解碼？（建議 Phase 1 先略過）

---

## 5. 頁面 / 畫面清單（Phase 1）

1. **登入 / 註冊**
2. **聯絡人列表**（搜尋框、標籤篩選、+ 新增按鈕）
3. **拍照頁**（正面/背面兩格、相機或選圖、上傳進度）
4. **擷取確認頁**（左：原圖；右：可編輯欄位表單，標示 AI 信心或留空欄位）
5. **聯絡人詳情**（顯示全部欄位、原始名片照、可進編輯）
6. **聯絡人編輯**

---

## 6. 成功指標（建議）
- 擷取準確率：核心欄位（姓名/公司/電話/Email）正確率 ≥ 90%
- 單張名片從拍照到存檔 < 30 秒
- 使用者願意持續使用（留存）
